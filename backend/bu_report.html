Why this happens

Mine produces a monotonically decaying pattern (1,600 → 1,280 → 1,024 → 1,024 → 386) — the DP picks effCap = lSf × pricedFrac × h each day until SFS depletes.

CSV produces a non-monotonic pattern (1,600 → 1,280 → 1,170 → 94 → 1,170) — the model picks higher on D4, dips on D5, then jumps back up on D6.

The colleague's tech doc says floor enforcement is "proportional scaling then a greedy top-up across days, prioritised by FAST-mode days." For High-8 and High-9, all days are HOLD, so the FAST-priority ordering doesn't apply. The doc does not specify the secondary ordering rule that produces the 1,170 / 94 / 1,170 pattern.

Verified not the cause

Comprehensive parameter sweeps confirmed none of the following changes resolve the High-8/9 divergence:

  • candidates_per_day: 10, 11, 12, 13, 14, 15, 16 — no change
  • hold_capacity_base × hold_capacity_slope: 6 different combinations — no change
  • gamma_discount: 0.80, 0.85, 0.92, 0.95, 0.99 — no change
  • lambda_cost: 0.3, 0.5, 0.7, 0.9 — no change
  • weekly_cap_penalty: 50, 100, 150, 200, 300, 500, 800 — no change for High-8/9
  • Opening vs running pricedFrac in enforceMonthlyMin — opening matches CSV better; already applied
  • Removing the HOLD-mode priced-excess penalty — no change for High-8/9
Alignment ceiling: the remaining 12-day distribution difference appears to be the result of a non-obvious greedy-ordering rule in the colleague's floor-enforcement pass that the tech doc doesn't surface. Without access to their Python source, this is the alignment ceiling.
